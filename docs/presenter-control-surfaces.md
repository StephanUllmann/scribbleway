# Presenter Control Surfaces: Prior Art

Date: 2026-07-29
Status: Research

## Context

Scribbleway's tray popup currently packs roughly twenty controls into a single 432×550 scrolling panel — a shape that forces a live presenter to look away from their audience/screen to find a control. A separate ticket will design Scribbleway's own control surface; this document is not that design. It is a primary-source survey of how five comparable tools (Excalidraw, Gromit-MPX, Epic Pen, ZoomIt, Krita's pop-up palette) plus what could be verified for macOS/OBS handle the same underlying problem: giving a person mid-task (presenting, annotating, streaming) a way to change tool, color, or width without breaking their flow. Every claim below is cited to the tool's own docs, source, or official support pages.

## Excalidraw

Sources: [Excalidraw keyboard shortcuts](https://docs.excalidraw.com/docs) reachable in-app via `?`/`Shift+/` (confirmed via [GitHub issue #3100](https://github.com/excalidraw/excalidraw/issues/3100) discussing shortcut gaps), and the shortcut table defined in source at [`packages/excalidraw/actions/shortcuts.ts`](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/actions/shortcuts.ts).

1. **Blind-reachable controls**: Every tool has a single-letter or numeral hotkey — Selection `V`/`1`, Rectangle `R`/`2`, Diamond `D`/`3`, Ellipse `O`/`4`, Arrow `A`/`5`, Line `L`/`6`, Draw (freehand) `P`/`7`, Text `T`/`8`, Insert image `9`, Eraser `E`/`0`, Frame `F`, Laser pointer `K`, Hand/pan `H` (per the docs summary and source shortcut table). Editing actions are also hotkeyed: undo/redo, group/ungroup (`CtrlOrCmd+G`/`CtrlOrCmd+Shift+G`), lock element (`CtrlOrCmd+Shift+L`), duplicate (`CtrlOrCmd+D`), flip horizontal/vertical (`Shift+H`/`Shift+V`), tool-lock to keep a tool active after use (`Q`), zoom in/out/reset, and a command palette (`CtrlOrCmd+/` or `CtrlOrCmd+Shift+P`) that exposes the rest by name rather than by memorized position. Per the [source shortcut table](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/actions/shortcuts.ts), stroke/background color and stroke-width/style are **not** in the hotkey table (`addToLibrary` is likewise explicitly excluded), i.e. property values themselves are not blind-settable by default hotkey — this matches a still-open feature request tracked in [issue #3100, "Keyboard shortcuts for changing stroke and background colors"](https://github.com/excalidraw/excalidraw/issues/3100).
2. **On-canvas vs. panel vs. hidden**: Tool selection lives in a toolbar. The property panel component itself, [`packages/excalidraw/actions/actionProperties.tsx`](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/actions/actionProperties.tsx), defines controls for: stroke color (`labels.stroke`), background/fill color (`labels.changeBackground`), fill style — hachure/cross-hatch/solid/zigzag (`labels.fill`), stroke width — thin/medium/bold (`labels.strokeWidth`), sloppiness — architect/artist/cartoonist (`labels.sloppiness`), freedraw stroke variability — constant/variable (`labels.pressure`), stroke style — solid/dashed/dotted (`labels.strokeStyle`), opacity as a 0–100 slider (`labels.opacity`), edge roundness — sharp/round (`labels.edges`), arrowheads and arrow type (`labels.arrowheads`, `labels.arrowtypes`), plus text-specific controls (font size, font family, text/vertical alignment) that only render for text elements. This is the panel that appears whenever a drawing tool is active or an element is selected — these are the same properties this task's Q3 (roughness/opacity disclosure) is asking about, so the source is the component that actually renders them, not a documentation page. The full inventory of every other action (save, export, canvas search, stats overlay via `Alt+/`) is otherwise reachable only through the command palette or main menu, not shown by default. Note: [`docs.excalidraw.com`'s "Customizing Styles" page](https://docs.excalidraw.com/docs/@excalidraw/excalidraw/customizing-styles) — despite the name — covers only CSS theme-variable overrides for embedders, not this drawing-property panel, and is not a useful citation for Q2/Q3.
3. **Advanced/rare property disclosure**: Per the same `actionProperties.tsx` source, "sloppiness" (architect/artist/cartoonist roughness presets) is rendered by the identical panel component as stroke color, width, and opacity — it is not gated behind a secondary tab or "advanced" toggle; every property listed in point 2 is exposed at the same level, all-at-once, whenever the panel is showing.
4. **Decisions before first mark**: [`plus.excalidraw.com`'s "How to start" guide](https://plus.excalidraw.com/how-to-start) documents `R` as the rectangle-tool shortcut but does not state what tool is pre-selected on a fresh canvas load — this detail is **unverified** against a primary source and is not asserted here.

## Gromit-MPX

Source: [bk138/gromit-mpx README](https://github.com/bk138/gromit-mpx/blob/master/README.md), the shipped default config [`data/gromit-mpx.cfg`](https://github.com/bk138/gromit-mpx/blob/master/data/gromit-mpx.cfg), and open issue [bk138/gromit-mpx#91](https://github.com/bk138/gromit-mpx/issues/91).

1. **Blind-reachable controls**: `F9` toggles painting on/off, `Shift+F9` clears the screen, `Ctrl+F9` toggles overlay visibility, `Alt+F9` quits, `F8` undoes the last stroke, `Shift+F8` redoes it — all stated in the README and rebindable via `--key`/`--undo-key` command-line flags. Tool switching itself is also blind: in the shipped default config, holding no modifier draws with "red Pen," holding `Shift` switches to "blue Pen," `Ctrl` to "yellow Pen," `Alt` to "blue Circle," `Alt+Shift` to "red Filled Circle," and mouse buttons 2/3 select "green Marker"/"Eraser" — all read directly from `data/gromit-mpx.cfg`. Per open issue [#91](https://github.com/bk138/gromit-mpx/issues/91), this is a **hold**-to-use binding, not a persistent selection: "someone must press and hold a key defined in the gromit-mpx.cfg file in order to change to another pen," and the issue (still open) is a feature request to add persistent tool selection via tray icon or CLI flag (`gromit-mpx -t "Red pen 1"`) — confirming no such persistent-selection UI exists as of this writing.
2. **On-canvas vs. panel vs. hidden**: There is no on-screen panel by design. The README states the tool's philosophy directly: it "does not get into your way of doing things by sticking some UI widget on your desktop, potentially obscuring more important contents. It does provide a UI, but only in form of a tray icon." All tool/color/size definitions live in the text config file `gromit-mpx.cfg` (in `$XDG_CONFIG_HOME`), edited outside the running application; canvas opacity is set via the `-o <opacity>` command-line flag. Nothing is exposed as clickable on-canvas controls.
3. **Advanced/rare property disclosure**: Every property (pen size, color, arrow ends, fill, line smoothing, orthogonal snapping) is defined per-tool in the config file, with tools able to inherit and override each other's settings (e.g. `"blue Pen" = "red Pen" (color="blue");`, from the README). None of this is disclosed progressively in a UI — it is all-or-nothing: either the operator edits the config file, or they get the shipped defaults.
4. **Decisions before first mark**: Zero UI decisions beyond installing/launching — the default config's no-modifier binding is already a usable pen, so pressing `F9` then dragging the pointer produces a stroke with no menu, dialog, or tool click involved.

## Epic Pen

Source: [Epic Pen User Guide](https://epicpen.com/userguide), [epicpen.com](https://epicpen.com/), and the [Epic Pen FAQ](https://epicpen.com/faq).

1. **Blind-reachable controls**: The User Guide states shortcuts exist for "toggling visibility, selecting the cursor, pen, highlighter and eraser, undoing actions, clearing the screen, taking snapshots, as well as for increasing or decreasing the stroke size" and gives concrete examples: Highlighter `Ctrl+Shift+4`, Eraser `Ctrl+Shift+5`, Undo `Ctrl+Shift+6`. All hotkeys are user-remappable (Menu → Settings → Hotkeys, per the FAQ), and on macOS the app additionally requires Accessibility permission for hotkeys to fire while another app has focus (per the FAQ). A "Ghost Mode" is documented that lets the operator "work using only shortcuts leaving the screen free" — i.e. the toolbar itself can be dismissed while keeping the tool fully hotkey-driven.
2. **On-canvas vs. panel vs. hidden**: A movable, dismissible toolbar ("unobtrusive toolbar," with a documented "Hide Toolbar" option for presenting) carries pen/eraser/highlighter/shapes/text/screenshot tools and color swatches (16 colors free, 24 on Pro, per epicpen.com). Hotkey remapping, tablet-stylus-button mapping, and the Accessibility-permission grant live in Settings, reachable only via the toolbar's menu, not on-canvas (per the FAQ).
3. **Advanced/rare property disclosure**: Fading Ink (auto-disappearing strokes, with short/medium/long duration options) and Whiteboard/Blackboard background toggles are both described as directly reachable, always-available features rather than settings-menu-only options, per epicpen.com's feature list. Opacity and line-style controls beyond stroke size were **not found** documented on any fetched Epic Pen page and are not asserted here.
4. **Decisions before first mark**: The User Guide's own framing is "simply select the desired tool and start annotating" — implying one tool click (or hotkey press) is the only decision before a stroke, though the guide does not state whether a tool is pre-selected at launch.

## ZoomIt

Source: [ZoomIt — Sysinternals | Microsoft Learn](https://learn.microsoft.com/en-us/sysinternals/downloads/zoomit) (official, authored by Mark Russinovich).

1. **Blind-reachable controls**: ZoomIt is close to entirely keyboard-driven. Mode entry: Zoom Mode `Ctrl+1`, Draw-without-zoom `Ctrl+2`, LiveZoom `Ctrl+4`, LiveDraw `Ctrl+Shift+4`, countdown timer `Ctrl+3`, screen recording `Ctrl+5`, DemoType `Ctrl+7`, panorama recording `Ctrl+8`. While drawing: color/tool selection is single-letter — Red `R`, Green `G`, Blue `B`, Yellow `Y`, Orange `O`, Pink `P`, plus `Shift+<letter>` for the highlighter variant of each color, and Blur pen `X`. Shape modifiers are held while dragging: `Shift` forces a straight line, `Ctrl` a rectangle, `Tab` an ellipse, `Ctrl+Shift` an arrow. Line/cursor size and font size scale with `Ctrl+scroll` or arrow keys; `Space` centers the cursor; `Ctrl+Z` undoes the last drawing, `E` erases all; `W`/`K` swap to a whiteboard/blackboard background; `T`/`Shift+T` type left/right-aligned text; `Esc` or right-click exits. This is the densest blind-operable hotkey surface of any tool surveyed here — the full table is reproduced on the Microsoft Learn page.
2. **On-canvas vs. panel vs. hidden**: There is effectively no persistent on-screen panel during use — ZoomIt "runs unobtrusively in the tray and activates with customizable hotkeys." The only UI surface is a one-time (or manually reopened) configuration dialog, shown on first run, that "describes ZoomIt's behavior, lets you specify alternate hotkeys for zooming and for entering drawing mode without zooming, and customize the drawing pen color and size" — i.e. setup is front-loaded into a dialog, and everything after that is keyboard/mouse gesture with no chrome.
3. **Advanced/rare property disclosure**: There isn't a disclosure hierarchy in the traditional sense — properties like line/cursor size, font size, and countdown-timer duration are all exposed the same way, as a held-modifier + scroll/arrow-key gesture while in the relevant mode, per the shortcut table. No property is described as sitting in a secondary panel once a mode is active.
4. **Decisions before first mark**: The first-run configuration dialog must be dismissed once (it "presents a configuration dialog that describes ZoomIt's behavior" on first launch). After that, entering draw mode is a single hotkey (`Ctrl+2` for draw-without-zoom, or `Ctrl+1` then left-click for zoom-mode drawing) with a pen color/size already configured from setup — i.e., one dialog dismissal ever, then one hotkey per session.

## Krita's Pop-up Palette

Source: [Krita Manual — Pop-up Palette](https://docs.krita.org/en/reference_manual/popup-palette.html) and [Pop-up Palette Settings](https://docs.krita.org/en/reference_manual/preferences/popup_palette_settings.html).

1. **Blind-reachable controls**: The palette is summoned by a single mouse gesture — right-click on the canvas — which is muscle-memory-fast even though it is not a keyboard shortcut. Per the docs, the palette "can be accessed by right-clicking on the canvas, and a circular palette will spawn at the position of your mouse cursor" (i.e., it appears exactly where the hand already is, not at a fixed screen location the user must look for). The manual documents no default keyboard shortcut for invoking it; assigning one requires going into Settings → Configure Krita → Canvas Input Settings and manually binding "show popup palette" to a key combination — this is a documented workaround, not a shipped default.
2. **On-canvas vs. panel vs. hidden**: The palette itself is the on-canvas surface, spawned at the cursor rather than docked. It carries: foreground/background color swatches, a circular hue ring with a triangular saturation/lightness picker, a recent-color history strip, a brush-preset ring (first 10 presets of the active tag, default tag "My Favorite," count configurable), a tag switcher for the preset ring, a canvas-rotation dial, a zoom slider with a "reset to 100%" button, a canvas-only mode toggle (hides the rest of the UI chrome), and a mirror/flip button — all per the Krita Manual page. A ">" control on the palette gives on-canvas access to dockers, including the On-Canvas Brush Editor by default; other dockers can be added via settings. Everything not on the palette (full brush-preset library beyond the tag ring, layer management, most dockers) lives in Krita's conventional panel/docker system, reachable outside the palette.
3. **Advanced/rare property disclosure**: The manual documents the palette's contents as a fixed, always-the-same set (color, presets, rotation, zoom, canvas-only toggle, mirror, docker shortcut) — there's no secondary "advanced" tier described within the palette itself; anything beyond that set is outside the palette entirely, in the regular docker system.
4. **Decisions before first mark**: Not applicable in the same terms as the other tools — the pop-up palette is a mid-session convenience surface, not an app-launch flow, and the manual doesn't describe Krita's startup/first-stroke sequence, so no claim is made here.

## macOS: Preview Markup, Screen Sharing, and OBS

Three different surfaces were checked per the ticket's scope; findings vary sharply between them.

### Preview markup toolbar

Source: [Apple Support — Annotate an image in Preview on Mac](https://support.apple.com/guide/preview/annotate-an-image-prvw1501/mac).

- **Blind-reachable**: The support page documents no keyboard shortcuts for markup tools beyond a single modifier: holding `Option` while using the rotate tool rotates right instead of left. Everything else (tool selection, color, style) is not documented as hotkey-driven — this is **unverified as keyboard-accessible** and should be treated as click-driven.
- **On-canvas vs. panel vs. hidden**: All markup tools live in one dedicated Markup toolbar, shown/hidden via a toggle button. It groups selection tools (rectangular/elliptical/lasso/smart lasso), drawing tools (Sketch — single-stroke shape auto-recognition; Draw — pressure-sensitive on Force Touch trackpads; Shapes with draggable handles), annotation elements (Text, Sign/signature, Highlight, a magnifying Zoom lens), image tools (Instant Alpha background removal, Crop, Rotate), and styling controls (Shape Style for line thickness/type/shadows, Border Color, Fill Color, Text Style, Adjust Color for exposure/contrast/saturation/tint, Adjust Size), plus an Image Description field for alt text. Nothing described here is hidden in a settings menu — the whole toolbar is one flat, always-visible-once-toggled-on row.
- **Advanced/rare property disclosure**: Line thickness/type/shadow ("Shape Style") sits in the same toolbar row as color pickers — one click away, not nested. Per the support page, once an image is saved, its annotations become permanent ("you can't edit, move, or delete the annotations after you save"), which the page flags as a reason to convert to PDF first if further editing may be needed.
- **Decisions before first mark**: Open the file, click to show the Markup toolbar (if not already visible), then click a tool — two clicks minimum per the documented flow, before Sketch/Draw/Shapes produces a mark.

### macOS Screen Sharing (Screen Sharing.app / remote-control)

Source: [Apple Support — Share the screen of another Mac](https://support.apple.com/guide/mac-help/share-the-screen-of-another-mac-mh14066/mac).

- This page documents Dynamic Resolution, HDR, scaling/quality controls, Observe vs. Control modes, clipboard sharing, and file transfer, plus a customizable toolbar (`View > Customize Toolbar`) for surfacing these. **It contains no mention of any drawing, annotation, or markup capability anywhere on the page** — classic macOS Screen Sharing (the remote-control tool used via Finder/Messages "Share Screen") has no native annotation surface, per this primary source.

### FaceTime screen-sharing annotation (a distinct, separate feature from the above)

Source: [Apple Support — Manage Screen Sharing and Screen Control in FaceTime](https://support.apple.com/guide/personal-safety/manage-screen-sharing-control-facetime-ips48fe06838/web).

- Unlike classic Screen Sharing, FaceTime's newer screen-sharing mode does support drawing: the other party on the call can "tap, draw, or write on your screen (the circle, drawing, or writing disappears after a few seconds)." This is confirmed as ephemeral/auto-fading by design, per the quoted source text. The same source does not describe the access gesture, a color/tool palette, or a persistent toolbar for this feature — those specifics could not be verified against a primary source (secondary sources describe a tap-to-open pen/highlighter/color palette in the corner of the screen, but this was not confirmed on any Apple Support page reachable during this research and is therefore **not asserted** here).

### OBS

Source: [OBS Studio Overview (official)](https://obsproject.com/kb/obs-studio-overview) and [OBS Forums thread on an "annotation toolbar"](https://obsproject.com/forum/threads/how-to-get-annotation-toolbar-back.110237/).

- **OBS has no native annotation/drawing tool.** The official Overview page's full top-level section list — Quick Start, Settings, Scenes and Sources, Filters, Studio Mode, Testing/Finishing Up, Resource Links — makes no mention of drawing, annotation, or markup anywhere. A forum thread asking how to get an "annotation toolbar back" was answered by clarifying the poster was thinking of their PDF viewer's own annotation feature, not anything belonging to OBS ("Aren't you talking about the [PDF] Document Viewer annotation feature that has nothing to do with OBS?"). Third-party plugins (e.g. a community "Draw" plugin) exist to add this capability, but that is explicitly outside OBS itself.

## Patterns that recur

- **Modifier-key or single-letter tool/color switching without opening any panel.** ZoomIt (`R`/`G`/`B`/`Y`/`O`/`P` for colors, per the [Microsoft Learn shortcut table](https://learn.microsoft.com/en-us/sysinternals/downloads/zoomit)) and Gromit-MPX (held `Shift`/`Ctrl`/`Alt` selecting a different pre-configured pen, per [`gromit-mpx.cfg`](https://github.com/bk138/gromit-mpx/blob/master/data/gromit-mpx.cfg)) both bind color/tool choice directly to a held or tapped modifier/letter rather than a menu click. Excalidraw does the same for tool selection (`V`/`R`/`O`/`A`/`L`/`P`/`T`/`E`, per [source](https://github.com/excalidraw/excalidraw/blob/master/packages/excalidraw/actions/shortcuts.ts)), though not for color.
- **A mostly-chromeless runtime state, with setup front-loaded into a one-time dialog or external config file.** Gromit-MPX pushes all tool/color/size definition into a config file edited outside the running app, leaving zero on-screen UI during use (per its [README](https://github.com/bk138/gromit-mpx/blob/master/README.md)). ZoomIt front-loads pen color/size into a first-run configuration dialog, after which "ZoomIt runs unobtrusively in the tray" with no persistent panel (per [Microsoft Learn](https://learn.microsoft.com/en-us/sysinternals/downloads/zoomit)). Both push configuration to a moment before or outside the drawing action itself, rather than surfacing it continuously on screen.
- **A tool surface that spawns at/near the cursor rather than a fixed screen location.** Krita's pop-up palette spawns "at the position of your mouse cursor" on right-click, an on-canvas UI element placed wherever the hand already is (per the [Krita Manual](https://docs.krita.org/en/reference_manual/popup-palette.html)). ZoomIt has a related but not identical behavior: none of its controls are cursor-anchored UI, but its drawing-mode interaction is still pointer-centric — a `Space` press "centers the cursor" mid-draw and every drawing gesture (color keys, shape-modifier holds) executes wherever the pointer currently is rather than requiring a trip to a fixed toolbar (per [Microsoft Learn](https://learn.microsoft.com/en-us/sysinternals/downloads/zoomit)). Both avoid making the operator's eyes leave the work area to find a control, even though the mechanism differs (a spawned widget vs. a purely keyboard/pointer gesture).
- **A dismissible/hideable toolbar, kept as an escape hatch rather than the primary interaction path for fluent users.** Epic Pen documents a "Hide Toolbar" option for presenting and a "Ghost Mode" for shortcut-only operation with the screen left clear (per the [User Guide](https://epicpen.com/userguide) and [epicpen.com](https://epicpen.com/)). Gromit-MPX's entire design philosophy is to avoid "sticking some UI widget on your desktop," exposing only a tray icon (per its [README](https://github.com/bk138/gromit-mpx/blob/master/README.md)). Both treat a visible on-screen panel as optional scaffolding, not the thing a fluent user actually touches.

## What could not be verified

- **Epic Pen's full shortcut list**: only three example bindings (Highlighter, Eraser, Undo) and the general claim that shortcuts exist for tool/color/size/undo/clear/snapshot were found on [epicpen.com/userguide](https://epicpen.com/userguide) and the [FAQ](https://epicpen.com/faq); the "user manual" both pages point to as the complete reference could not be located as a fetchable primary-source page.
- **Epic Pen opacity/line-style controls**: not documented on any Epic Pen page reached during this research; not asserted.
- **Excalidraw's default pre-selected tool at launch**: [plus.excalidraw.com/how-to-start](https://plus.excalidraw.com/how-to-start) does not state this, and no other Excalidraw-owned page confirming it was found.
- **Excalidraw's panel behavior on narrow viewports** (e.g. whether properties collapse into a single popover on mobile-width screens): not confirmed against `actionProperties.tsx` or any other primary source reached during this research; not asserted in the body above.
- **Gromit-MPX man page**: the project does not appear to ship a separate man page distinct from its README (a targeted search for a `.1` man page file in the repository did not turn one up); the README was used as the primary source instead, per the task's own fallback allowance.
- **FaceTime screen-share annotation UI specifics** (access gesture, whether there's a persistent pen/highlighter/color palette): the only confirmed primary-source detail is the ephemeral tap/draw/write behavior from [Apple's Personal Safety guide](https://support.apple.com/guide/personal-safety/manage-screen-sharing-control-facetime-ips48fe06838/web); the iPhone/iPad user-guide pages describing this feature in more detail ([iPhone guide](https://support.apple.com/guide/iphone/share-your-screen-in-a-facetime-call-iph327b4b53c/ios)) returned only navigation/table-of-contents content through the fetch tool used, not the article body, despite repeated attempts.
- **Krita's startup/first-stroke decision count**: the Pop-up Palette manual page documents the palette itself, not Krita's app-launch flow, so no decisions-before-first-mark figure is given for Krita.
